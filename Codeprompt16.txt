# MASTER PROMPT — CIVICX COMPLETE UI/UX DESIGN

You are a Senior UI/UX Designer and Senior Frontend Developer.

Design and implement a complete, modern, professional and mobile-first UI for **CivicX — Your Neighbourhood, Connected.**

CivicX is a neighbourhood-based community platform that connects citizens, local businesses, workers, service providers and communities.

The application must bring all CivicX features into one consistent, easy-to-use interface.

IMPORTANT: Do not design CivicX as a basic admin dashboard or a collection of unrelated pages. It should feel like a modern consumer application that ordinary people can use every day.

---

# 1. DESIGN VISION

Create a UI inspired by the usability and visual quality of:

- Google Maps — location and nearby discovery.
- Instagram — photo and video feeds.
- Google Business Profiles — local business discovery.
- Reddit — community discussions and updates.
- Modern news applications — readable local news.
- Modern service platforms — worker and service discovery.

Do not copy these applications. Use them as design inspiration and create a unique CivicX identity.

Design principles:

- Clean and modern.
- Mobile-first and responsive.
- Easy for non-technical users.
- Simple navigation.
- Visually attractive.
- Fast and lightweight.
- Consistent design across every module.
- Accessible typography and colour contrast.
- Avoid overcrowded screens.

Product name: CivicX

Create reusable design tokens and components.

# 20. UI/UX QUALITY REQUIREMENTS

- Use realistic sample data instead of empty screens.
- Use consistent icons.
- Use proper image aspect ratios.
- Keep content readable.
- Use meaningful empty states.
- Add skeleton loading states.
- Add validation and error states.
- Make forms easy to complete.
- Avoid unnecessary animations.
- Avoid excessive gradients.
- Avoid oversized cards.
- Avoid cluttered dashboards.
- Make every navigation item functional.
- Ensure all screens are responsive.
- Ensure keyboard accessibility.
- Use appropriate image fallbacks.

The design must feel like a real, usable product rather than a static design prototype.

# 21. IMPLEMENTATION RULES

Before implementing:

1. Inspect the existing CivicX frontend repository.
2. Identify its framework, routing, styling and component structure.
3. Reuse the existing stack.
4. Inspect available backend APIs.
5. Identify which screens can use real APIs and which need sample data.
6. Preserve existing functionality.

Do not:
- Rewrite the entire application.
- Change backend architecture unnecessarily.
- Invent API endpoints and pretend they work.
- Duplicate existing pages.
- Add unnecessary dependencies.
- Hardcode sensitive data.
- Break existing authentication or role-based access.

If a backend API is not available, use clearly separated mock data and design the interface so it can later connect to real APIs.

Do not present mock functionality as production functionality.
