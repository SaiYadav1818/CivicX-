Important backend engineering considerations
Because payment systems can receive duplicate callbacks, you need:

Idempotency keys.

Unique provider transaction IDs.

Webhook signature verification.

Database transactions.

Optimistic locking or appropriate row locking for concurrent contributions.

Retry handling for temporary provider failures.

Scheduled reconciliation.

Separate payment and payout status machines.

For example, if a provider sends the same successful payment webhook three times, JanSeva must record only one successful contribution and one set of accounting entries.
