Example: complaints table
CREATE TABLE complaints (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,

    complaint_number VARCHAR(50) UNIQUE NOT NULL,

    citizen_id BIGINT NOT NULL,
    department_id BIGINT,
    category_id BIGINT NOT NULL,

    title VARCHAR(200) NOT NULL,
    description TEXT,

    latitude DECIMAL(10,7),
    longitude DECIMAL(10,7),

    address VARCHAR(500),

    priority VARCHAR(20) DEFAULT 'MEDIUM',

    status VARCHAR(30) DEFAULT 'SUBMITTED',

    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
        ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_citizen (citizen_id),
    INDEX idx_department_status (department_id, status)
);


Complaint status lifecycle
Use a controlled state machine instead of allowing arbitrary status updates.
SUBMITTED
Citizen submits complaint


UNDER_REVIEW
Department reviews complaint


ASSIGNED
Worker assigned


IN_PROGRESS
Worker starts resolution


RESOLVED
Worker submits completion evidence


CLOSED
Citizen confirms resolution


Additional paths: REJECTED, REOPENED and ESCALATED, with permission and reason checks.

Important database practices:
- Use foreign keys.
- Add indexes to frequently searched columns.
- Store images in object storage, not directly in MySQL.
- Keep complaint history immutable.
- Use transactions for critical updates.
- Use pagination for complaint listings.
- Add created-by and updated-by audit information.
