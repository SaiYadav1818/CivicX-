2. Citizen uploads one or more photos of a civic issue.
3. Application captures GPS coordinates and location details.

# 4. Advanced Duplicate Complaint Detection

This is one of the most important features.

When a new complaint is submitted, compare it with existing complaints to determine whether the same civic issue has already been reported.

Use multiple comparison conditions.

### A. GPS proximity

Compare the new complaint's latitude and longitude with existing complaints.

Example:

- Complaint A: 17.4840, 78.3910
- Complaint B: 17.4842, 78.3912

These reports may refer to the same physical issue.

Use a geospatial distance calculation such as the Haversine formula or MySQL spatial functions.

Make the search radius configurable by issue category. For example, a pothole and a large garbage dump may need different proximity thresholds.

### B. Image similarity

Use an image embedding model to convert each image into a numerical vector.

Compare embeddings using cosine similarity or another appropriate similarity metric.

Example:

- Similarity above 0.95: very strong visual match.
- Similarity between 0.85 and 0.95: possible match.
- Similarity below 0.85: weaker match.

These values are initial configuration examples, not universal thresholds. Calibrate them using real JanSeva images.

Also use perceptual hashing to detect identical or resized copies of uploaded images.

### C. Category matching

Compare:

- AI-detected category
- Citizen-selected category
- Existing complaint category

For example, a new garbage complaint should be compared primarily with nearby garbage complaints, not every issue in the area.

### D. Time comparison

Compare when the previous complaint was submitted.

A complaint about a pothole reported three months ago may still be relevant if it remains unresolved.

Do not automatically ignore older unresolved complaints.

Consider:

- Complaint creation time
- Last status update
- Resolution status
- Latest evidence
- Whether the issue is still active

### E. Description similarity

Use text similarity or semantic embeddings to compare complaint descriptions.

Example:

- "Garbage dumped beside the main road."
- "Waste is accumulating near the roadside."

These descriptions may refer to the same problem.

### F. Combined duplicate score

Create a configurable duplicate detection algorithm using:

- GPS distance
- Image similarity
- Perceptual hash
- Issue category
- Description similarity
- Complaint status
- Submission time

Return a structured result:

```json
{
  "duplicateCheckCompleted": true,
  "possibleDuplicate": true,
  "duplicateScore": 0.93,
  "matchingComplaints": [
    {
      "complaintNumber": "JS-2026-00125",
      "distanceMeters": 18.5,
      "imageSimilarity": 0.94,
      "categoryMatch": true,
      "status": "IN_PROGRESS"
    }
  ],
  "recommendedAction": "ADMIN_REVIEW"
}
```

### G. Duplicate handling rules

Implement these rules:

- Very high match: ask the citizen whether they want to view the existing complaint and submit additional evidence.
- Possible match: allow submission but flag it for admin review.
- No match: create a normal complaint.
- Existing complaint resolved: do not automatically merge a new report; the issue may have returned.
- Existing complaint rejected: do not automatically merge.
- Multiple matching complaints: show the most relevant matches to the admin.
- Admin can confirm duplicate, reject duplicate suggestion or link complaints.

**Important:** Never silently delete or discard a citizen's complaint. Preserve the original report and its audit history.

Support linking duplicate reports to a primary complaint while retaining each citizen's contribution and evidence.
